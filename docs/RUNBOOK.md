# 뉴스봇 운영 설명서

갱신: 2026-11-07 · 현재 단계: M7 릴스 켬 (첫 실제 릴스 게시를 기다리는 중, 다음: M8 성과 리포트)

M6 확인: 2026-11-05 00:45 게시분을 GitHub에서 미리보기 → 아래 키보드로 모두 승인 → GitHub 게시까지 한 바퀴 성공(인스타 2건).

새 인스타 채널(예: 심리테스트)을 만들 때는 [NEW_CHANNEL.md](NEW_CHANNEL.md) 순서를 따릅니다.

Cloudflare 시계가 깨우고 GitHub Actions가 실행합니다(둘 다 무료). 매일 할 일은 텔레그램 승인뿐입니다.

## 자동 실행 (M6, Cloudflare 시계 + GitHub Actions)

**Cloudflare 시계**(`clock/` 폴더, Worker 이름 `newsbot-clock`)가 **10분마다**(정각·10·20…분) GitHub를 깨우고, 깨어난 GitHub(`tick` 작업)가 "지금 할 일이 있나?"를 보고 있을 때만 미리보기·게시를 합니다 (2026-11-06부터). 시계는 판단하지 않고 "지금 돌아!" 신호만 보냅니다. 비용은 둘 다 0입니다(아래 '비용').

| 할 일 | 언제 하나 | 하는 일 |
|---|---|---|
| 깨우기 (시계, Cloudflare) | 10분마다 (정각·10·20…분) | GitHub `tick`에 "돌아" 신호 한 번. 못 깨우면 텔레그램 알림(한 시간에 1번) |
| 미리보기 (generate) | 게시 시각 **90~30분 전** 창에 들어온 첫 깨어남 → 시계가 제때 깨우면 **90분 전** | 수집 → Claude 작성 → 카드 → 텔레그램 미리보기 + 아래 키보드 버튼 |
| 게시 (publish) | 게시 시각이 **지난 뒤** 첫 깨어남 → 시계가 제때 깨우면 **게시 시각 정각**에 깨어남 | 버튼 응답 읽기 → 승인된 것만 게시 → 링크 보고. 안 누른 것은 "⌛ 건너뛰었어요" |
| 점검·정리 (maintenance) | 월요일 04:10 GitHub 예약 (몇 시간 늦어도 상관없는 작업) | 인스타 연결 점검(문제 시 텔레그램 알림), 7일 지난 초안 정리 |

| 게시 시각 | 미리보기가 오는 때 | 올라가는 때 |
|---|---|---|
| 07:30 | 06:00 깨어나 **06:02~06:10쯤** 도착 (늦어도 07:00) | 07:30 깨어나 **07:31~07:42쯤** |
| 12:00 | 10:30 깨어나 **10:32~10:40쯤** 도착 (늦어도 11:30) | 12:00 깨어나 **12:01~12:12쯤** |
| 18:00 | 16:30 깨어나 **16:32~16:40쯤** 도착 (늦어도 17:30) | 18:00 깨어나 **18:01~18:12쯤** |
| 21:30 | 20:00 깨어나 **20:02~20:10쯤** 도착 (늦어도 21:00) | 21:30 깨어나 **21:31~21:42쯤** |

(시계가 정각·10·20…분에 깨우므로 미리보기는 꼭 **90분 전** 깨어남에, 게시는 **게시 시각 정각** 깨어남에 걸립니다. 첫날 밤 실제: 11-06 20:00 깨어나 미리보기 → 21:30 깨어나 21:32 게시 → 11-07 06:01 깨어나 06:02 미리보기 도착. 올라가는 때의 1~12분은 GitHub 컴퓨터가 카드 그리는 도구를 설치하는 시간입니다(보통 2분 안, 가끔 10분). '늦어도'는 시계가 고장 나 GitHub 자체 예약만 남았을 때의 창입니다.)

- **왜 이렇게 바꿨나 (2026-11-06)**: 처음엔 시각 8개(06:23·07:32…)에 예약(cron)을 걸었는데, 11-05·06 이틀 동안 GitHub가 그 예약을 **매번 4~11시간 늦게** 보내거나 보내지 않았습니다. 저장소·계정 설정(공개 저장소, 기본 브랜치, Actions 켜짐, 포크 아님, 60일 활동 등)은 전부 정상이었고, 수동 실행(Run workflow)은 매번 바로 됐습니다. GitHub 공식 문서도 예약은 "바쁠 때 늦을 수 있고 일부는 버려질 수 있다"고 적어 두었고, 같은 기간 GitHub Actions 장애가 5건(11-04~06) 기록됐습니다. 그래서 '정해진 시각 하나'에 기대지 않고 10분마다 깨어나 **현재 시각 기준으로** 판단하게 했습니다. 예약이 몇 시간 늦게 와도 그때 맞는 일을 하고, 한 번 빠져도 다음 깨어남이 이어받습니다. 처음엔 GitHub Actions 안에서만 해결하려 했지만, 그날 13시간 동안 GitHub 예약이 한 번도 오지 않아(tick 예약 0회) 저녁에 **깨우는 시계만 Cloudflare로 옮겼습니다**(Cloudflare도 무료임을 확인한 뒤의 결정). 시계는 수동 실행(workflow_dispatch)과 같은 신호를 보내는데, 이 신호는 이틀 동안 매번 바로 처리됐습니다.
- 시계가 제때 깨우면 미리보기는 게시 **90분 전쯤**(위 표), 게시는 **게시 시각 + 1~12분**에 올라갑니다. 시계가 고장 나 GitHub 자체 예약만 남으면 몇 시간 늦을 수 있습니다. 소개 글·카드에 시간을 적지 않는 이유입니다.
- 미리보기가 창(90~30분 전) 안에 아예 안 왔으면 그 시각은 그냥 넘어갑니다(아무것도 안 올라감). Claude에게 "미리보기 만들어줘"라고 하면 바로 만듭니다.
- **시계가 GitHub를 깨우지 못하면** 텔레그램에 "⏰ 뉴스봇 시계가 GitHub를 깨우지 못했어요"와 이유·할 일이 옵니다(한 시간에 한 번만). 가장 흔한 이유는 GitHub 토큰 만료(응답 401) → 아래 '시계 켜기' 1~3번을 다시 합니다. 토큰을 아직 넣지 않았을 때는 알림 없이 조용히 기다립니다.
- **❌ 게시 실패가 왔는데 인스타에는 올라가 있을 때**: 인스타가 글을 올려 놓고도 "오류"라고 답하는 경우가 있습니다(2026-11-07 21:30, 응답 403 코드 4-2207051 "커뮤니티를 보호하기 위해 특정 활동을 제한합니다" = 자동 게시를 스팸으로 잠깐 의심). 그래서 오류가 나면 3초 뒤 최근 글 5개에서 같은 글을 찾아 올라가 있으면 성공으로 기록하고 릴스로 넘어갑니다("📸 올라가 있었어요"로 옵니다). 정말 안 올라갔으면 ❌와 안내가 오고, 인스타 앱에 안내가 떠 있으면 '실수예요'를 누른 뒤 몇 시간 뒤 Claude에게 "다시 올려줘"라고 하면 됩니다. 다시 올릴 때도 먼저 최근 글 25개(사흘치)를 확인하므로 그 안에서는 같은 글이 두 번 올라가지 않습니다.
- GitHub 자체 예약(10분마다, 4·14·24…분)도 **보조로** 남겨 두었습니다. 늦게라도 오면 같은 판단을 하므로 해롭지 않고, 시계가 고장 났을 때 뒤늦게라도 이어받습니다.
- 비용: **Cloudflare** 무료 요금제 — 하루 요청 10만 번(계정 합산) 중 뉴스봇 시계 144번(10분마다) + 함께달력 알림 1,440번(1분마다), 예약(cron) 5개 중 2개 사용(함께달력 알림 1 + 뉴스봇 시계 1), 1번 실행에 CPU 10ms 한도(실제 1~2ms). 카드 등록 없음, 한도를 넘으면 요금이 아니라 **멈출 뿐**입니다(매일 오전 9시에 다시 채워짐). **GitHub Actions** — 공개 저장소라 0. 할 일이 없는 깨어남은 30초쯤 돌고 끝납니다. **Claude** — 전과 같이 게시물당 약 $0.002~0.004.
- 미리보기 창의 길이는 `accounts/today_news.yaml`의 `generate_window_minutes: [30, 90]`(게시 30~90분 전)로 바꿀 수 있습니다.
- 실행 기록 보기: 저장소 → **Actions** 탭 → `tick`. 실행 이름에 누가 깨웠는지 보입니다: `tick · cloudflare`(시계), `tick · GitHub 예약`(보조 예약), `tick · manual`(직접 실행). 초록 ✓ = 성공, 빨간 ✗ = 실패(텔레그램에도 이유가 옵니다). 할 일이 없던 실행은 '미리보기 만들기'·'게시' 단계가 회색(건너뜀)입니다.
- 직접 실행: Actions 탭 → 왼쪽에서 generate 또는 publish 선택 → **Run workflow**. generate는 게시 시각(HH:MM)과 "샘플 문구(비용 0)"를, publish는 특정 초안 ID를 넣을 수 있습니다. 보통은 Claude에게 부탁하면 됩니다. 같은 때 tick이 돌고 있으면 뒤에 줄을 서는데, 대기 중인 실행이 2개가 되면 GitHub가 먼저 기다리던 것을 **Canceled**로 끝내니, 그렇게 끝났으면 한 번 더 실행합니다.
- **잠깐 멈추기**: Actions 탭 → `tick` 선택 → 오른쪽 위 `...` → **Disable workflow**. 다시 켤 때는 Enable. 꺼진 동안 시계가 깨워도 GitHub가 받지 않으므로 정각마다 '깨우지 못했어요' 알림이 올 수 있습니다. 하루 넘게 멈출 때는 Claude에게 "뉴스봇 멈춰줘"라고 하면 시계도 함께 멈춥니다(`clock/`의 cron을 비우고 다시 배포).
- 기록 보관: 승인 상태·사용한 기사·Claude 비용은 저장소의 `media` 브랜치(`state/`, `drafts/`)에 있습니다. 매번 새로 시작하는 GitHub 실행이 이 기록을 이어서 씁니다.
- 승인 전 초안의 글(draft.json)은 공개 저장소에 올라갑니다. 카드 이미지는 승인된 것만 올라갑니다.
- 공개 저장소는 60일 동안 활동이 없으면 예약 실행이 꺼질 수 있습니다. media 브랜치에 매일 기록이 쌓여 보통은 괜찮지만, Actions 탭에 꺼졌다는 안내가 보이면 Enable을 누릅니다.
- GitHub 컴퓨터(미국)에서는 전자신문 RSS가 열리지 않을 때가 있습니다(2026-11-04). 다른 언론사로 후보는 충분합니다.

### 시계 켜기 (Cloudflare Worker) — 한 번만

시계는 2026-11-06 18:42에 Cloudflare에 올렸고(함께달력 알림 서버와 같은 계정), 19:49에 **열쇠(GitHub 토큰)** 를 넣어 19:50부터 GitHub를 깨우고 있습니다. 아래는 토큰을 새로 만들 때(만료·분실) 다시 하는 순서입니다. 토큰이 없으면 시계는 10분마다 깨어나 "토큰 없음"만 기록하고 조용히 있습니다.

1. GitHub 토큰 만들기: github.com 로그인 → 오른쪽 위 프로필 → **Settings** → 왼쪽 맨 아래 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
   - Token name: `newsbot-clock` · Expiration: **No expiration**(만료 없음)을 고릅니다. 그 항목이 없으면 Custom으로 1년 뒤 날짜(7·30·60·90일을 고르면 그만큼 지나서 다시 발급해야 합니다) · Resource owner: xka119-cyber
   - Repository access: **Only select repositories** → `news-bot`
   - Permissions → Repository permissions → **Actions: Read and write** (Metadata는 자동으로 Read). 다른 권한은 건드리지 않음
   - **Generate token** → 값은 이때 한 번만 보입니다. 복사.
2. 메모장으로 `news-bot/.env`를 열면 맨 아래에 `GH_DISPATCH_TOKEN=` 줄이 있습니다(없으면 새 줄로 직접 씁니다). `=` 바로 뒤에 띄어쓰기 없이 붙여 넣고 저장합니다. 채팅에는 붙이지 않습니다.
3. Claude에게 "시계 비밀값 넣어줘"라고 합니다. `scripts/set_clock_secrets.py`가 `.env`의 토큰과 텔레그램 값 3개를 화면에 보이지 않게 Cloudflare로 옮기고, 등록된 **이름만** 보여 줍니다(2026-11-06 19:49 이렇게 넣음).
   - 훈의 터미널에서 직접 돌리면 `You are not authenticated` 또는 `non-interactive environment ... CLOUDFLARE_API_TOKEN` 오류가 납니다. Cloudflare 로그인(`wrangler login`)이 **Claude가 명령을 돌리는 환경에만** 되어 있고 훈의 터미널에는 없기 때문입니다(2026-11-06 확인). 직접 돌리고 싶으면 먼저 `clock/` 폴더에서 `npx wrangler login`을 한 번 하고(브라우저에서 허용) 같은 명령을 실행합니다.
   - 끝에 `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)`가 찍히면 Node(24) 종료 버그라 무시해도 됩니다. 성공 여부는 ✅/❌ 줄로 봅니다.
4. 확인: 10분 안에 Actions 탭에 `tick · cloudflare` 실행이 생기고, 그 뒤로 10분마다 이어집니다. (Claude에게 "시계 돌아가?"라고 물어도 됩니다.) 2026-11-06 19:50 첫 깨우기 성공.
   - **첫날 밤 결과**(11-06 19:50 → 11-07 07:00): 시계가 68번 깨워 **68번 모두** 실행됨(빠짐 0). 같은 11시간 동안 GitHub 자체 예약은 2번만 왔습니다(21:55, 04:52). 20:00 미리보기 → 21:30 게시(승인 후 21:32 올라감) → 06:01 미리보기까지 전부 시계가 처리했습니다.

- 지금 토큰은 **만료 없음**(No expiration)으로 만들었습니다(2026-11-06). 그래서 갱신할 일은 없고, GitHub에서 토큰을 지우거나 새로 만들었을 때만 1~3번을 다시 합니다. 토큰이 막히면 정각마다 텔레그램 알림(응답 401)이 옵니다.
- 시계 코드를 바꿨을 때 올리기: `clock/` 폴더에서 `npm run deploy` (처음 한 번 `npx wrangler login` — 이 PC는 함께달력 때 이미 로그인됨). 검사는 `npm test`(진짜 GitHub·텔레그램에는 요청 안 함).
- 시계 상태 보기: dash.cloudflare.com → Workers & Pages → `newsbot-clock` → Logs. 보통은 볼 일이 없습니다(문제는 텔레그램으로 옵니다).

### 비밀값 (Cloudflare 시계)
- Worker `newsbot-clock`에 3개: `GH_DISPATCH_TOKEN`(GitHub 깨우기), `TELEGRAM_BOT_TOKEN`·`TELEGRAM_CHAT_ID`(실패 알림). 위 '시계 켜기' 3번이 세 개를 한 번에 넣습니다(2026-11-06 19:49 3개 등록).
- 넣는 방법은 항상 `scripts/set_clock_secrets.py`(`.env` → Cloudflare, 값은 화면에 안 나옴). 이름만 확인하려면 `clock/`에서 `npx wrangler secret list`.

### 비밀값 (GitHub Secrets)
- 저장소 → Settings → Secrets and variables → Actions에 5개: `ANTHROPIC_API_KEY`, `IG_ACCESS_TOKEN`, `IG_USER_ID`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (2026-11-04 등록).
- 키를 새로 발급했으면 `.env`와 이곳 **두 군데 모두** 바꿔야 합니다. Claude에게 "뉴스봇 비밀값 다시 등록해줘"라고 하면 `.env` 값을 화면에 보이지 않게 옮겨 줍니다.

## 설계서와 달라진 점

- 메타가 이제 **비즈니스 포트폴리오**가 있어야 인스타 토큰을 줍니다(설계서에는 없던 단계).
- 인스타 토큰은 **시스템 사용자 토큰**(메타 화면 표기: 만료되지 않음)입니다. 설계서의 60일 연장 기능(M6)은 "토큰이 살아 있는지 점검" 위주로 바꿀 예정입니다.
- 이 토큰은 `graph.facebook.com` 주소에서만 작동합니다(설계서는 `graph.instagram.com`). 게시 코드(M5)는 이 주소와 API v26.0을 씁니다.
- 그래서 설계서의 주 1회 `token-refresh`(60일 토큰 갱신) 대신 `token-check`(연결 점검, 실패 시 텔레그램 알림)를 둡니다. `GH_PAT`는 필요 없습니다.
- 카드 이미지는 미리보기 때가 아니라 **승인된 뒤 게시 직전에만** 공개 주소(GitHub `media` 브랜치)에 올립니다. 건너뛴 초안은 공개되지 않습니다.
- 인스타 게시 한도는 설계서의 50건이 아니라 하루 100건입니다(메타 문서에 두 숫자가 섞여 있으나 계정 조회값은 100).
- 자동 실행은 설계서의 '시각별 예약(generate_lead_minutes: 60)' 대신 **10분마다 깨어나 판단하는 tick** 방식입니다(2026-11-06, 위 '자동 실행'). 설정도 `generate_window_minutes: [30, 90]`으로 바뀌었습니다.
- 릴스(M7)는 설계서의 2주 A/B 대신 **카드뉴스와 같이 둘 다** 올리고, 길이는 25~35초가 아니라 **약 15초**, 피드 공유 없이 릴스 탭에만 올립니다(2026-11-07 사용자 결정).
- 깨우는 시계는 GitHub 예약이 아니라 **Cloudflare Worker**(`clock/`, 무료)입니다(2026-11-06 저녁). GitHub가 수동 실행 신호를 받는 데 쓰는 GitHub 토큰(`GH_DISPATCH_TOKEN`, Actions 쓰기 권한)이 하나 더 필요합니다. 설계서의 `GH_PAT`(Secrets 권한)와는 다른 토큰입니다.

## 매일 할 일: 텔레그램 승인 (M4)

1. 게시 약 1시간 반 전(90분 전쯤, 늦어도 30분 전)에 @today3min_news_bot 대화방으로 **카드 4장 + 미리보기 메시지**가 옵니다. (시각마다 2개로 설정하면 2세트가 오고 제목에 (1/2), (2/2)가 붙습니다.)
2. 카드를 넘겨 보고, 메시지의 **⚠️ 확인할 점**(원문에 없는 숫자 등)을 봅니다. 원문 링크로 기사를 열어 볼 수 있습니다.
3. **입력칸 자리에 뜬 버튼**(아래 키보드)으로 고릅니다. 안 보이면 입력칸 옆 네모 4개 아이콘을 누릅니다.
   ```
   [✅ 승인 (07:30)]  [⏭ 건너뛰기 (07:30)]
   ```
   (시각마다 2개일 때는 `[✅ 모두 승인] [⏭ 모두 건너뛰기]` 와 `[✅ 1번 승인] [✅ 2번 승인]` 두 줄이 뜨고, 번호 버튼은 여러 개 눌러도 됩니다.)
   - 누르면 그 글자가 **내 메시지로** 대화방에 올라갑니다(정상).
   - 봇은 정해진 때만 깨어나서, 누른 즉시 답장은 없습니다. 게시 시각에 "✅ 승인됨", "📸 올라갔어요! + 링크"가 오고 버튼이 내려갑니다.
4. 안 누른 것은 게시 시각에 **올리지 않고** "⌛ 건너뛰었어요"가 옵니다. 지난 시각 것은 쌓이지 않고, 버튼은 늘 지금 기다리는 시각 것 하나만 뜹니다.

- **왜 아래 키보드인가 (2026-11-05)**: 메시지 안에 붙은 버튼은 봇이 2~3분 안에 대답하지 않으면 텔레그램이 누름 기록을 버립니다. 정해진 때만 깨어나는 봇은 그래서 승인을 못 읽었습니다. 아래 키보드 버튼은 글 메시지로 남아 24시간 보관됩니다.
- 게시 시각이 살짝 지나도 GitHub 실행이 아직이면(늦어지는 중) 누른 것이 반영됩니다. 실행이 끝난 뒤 누르면 "이미 처리됐거나 게시 시각이 지난 버튼이에요" 답장이 옵니다.
- 내 대화방에서 내 계정이 보낸 버튼 글만 인정합니다. 다른 사람이 같은 글을 보내도 승인되지 않습니다.
- 미리보기가 안 오거나 실패하면 같은 대화방에 "어느 단계에서, 왜" 실패했는지 메시지가 옵니다.
- 직접 해 보려면 Claude에게 "뉴스봇 미리보기 보내줘" → 버튼 누르기 → "뉴스봇 승인 확인해줘"라고 요청합니다.

- 영상은 파이썬 패키지 `imageio-ffmpeg`에 들어 있는 ffmpeg로 만듭니다(따로 설치 불필요, 무료).

## 더 많은 사람에게 보이게 하기 (2026-11-05)

인스타가 밝힌 노출 기준은 **본 시간, 도달 대비 좋아요, 도달 대비 보내기(DM 공유)**이고, 탐색 탭은 **저장·공유**를 많이 봅니다. 검색(인스타·구글)은 캡션 앞부분·대체 텍스트·프로필 이름의 **단어**를 봅니다. 해시태그는 분류용 3~5개면 충분합니다.

봇이 자동으로 하는 것:
- 캡션 첫 줄 = 표지 제목(핵심 단어), 둘째 줄 = 검색할 법한 질문
- "📌 저장해 두면… 친구에게도 보내 주세요" 한 줄 (저장·보내기 유도, 과한 구걸 문구는 금지)
- 해시태그 = Claude가 뽑은 기사 주제어 2~3개(예: #전월세안심신탁) + 고정 태그로 채워 5개
- 카드마다 대체 텍스트(alt text) — 화면 글을 그대로 옮김(숨은 키워드 넣지 않음)

사람이 해야 하는 것 (한 번만):
- 프로필 **이름 칸**에 검색어 넣기. 예: `오늘의 3분 뉴스 | 경제·생활 뉴스 요약` (아이디 말고 이름 칸)
- **소개글**에 "매일 4번, 출퇴근길 3분 경제·생활 뉴스 카드" + 누구를 위한 계정인지 한 줄
- 설정 → 개인정보 → **검색 엔진 색인(Search engine indexing)** 켜져 있는지 확인 (프로페셔널 계정은 기본 켜짐, 구글에도 노출)
- 댓글이 달리면 **그날 안에 답글** (초기 노출에 도움)
- 좋은 게시물은 **스토리로 공유**, 프로필에 **하이라이트** 하나 만들기

릴스(M7)는 2026-11-07부터 같이 올라갑니다(위 '릴스'). 나중에 (M8): 인사이트로 저장·보내기·탐색 유입 비율 보기, 잘 된 게시물 유형 찾기.
